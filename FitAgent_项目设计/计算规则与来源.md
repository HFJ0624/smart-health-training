# FitAgent 计算规则、来源与验收输入

版本：v1.0；核查日期：2026-10-12。本文规定 Java 计算服务的口径，LLM 只解释结果。未建立实际业务代码，因此“算例核对”不代表已经测试完整应用。

## 1. 统一约定

| 数据 | 单位或规则 |
|---|---|
| 体重、外部负重 | kg；两者不能混用 |
| 身高 | 输入 cm；BMI 内换算 m |
| 食物分量 | g，可食部；生熟与来源条目一致 |
| 热量 | kcal，即日常说的大卡；1 kcal = 4.184 kJ [R2] |
| 训练时长 | 存 seconds，公式中转 hours |
| 视频时间点 | 存 ms，界面转分秒 |
| 年龄 | 计算日相对于出生日期的完整周岁；不按毫秒除 365 天 |
| 小数 | 计算内部保留精度，展示时统一舍入；账本使用 BigDecimal |
| NULL | 未知或不适用；不能当 0 |
| 当前体重 | 采用计算日前最近一条有效测量；快照记录日期，较旧记录提示用户更新 |
| 历史计算 | 使用当时体重、条目及规则版本快照，不随新数据自动改写 |

规则引擎首版自动个体估算限制为 19–59 岁、无特殊医疗需求的常规健康人群。该范围是项目选择的保守子集：Mifflin 原研究为 19–78 岁健康成人，Adult MET 汇编为 19–59 岁。[R1][R4] 其他年龄仍可记录数据，但不套用不匹配的个体公式。怀孕、哺乳或用户声明需要专业指导时不自动生成个体热量与训练处方。

每个结果必须包含 `rule_code、rule_version、unit、input_snapshot、source、estimate_kind、missing_fields`。输入缺失时返回原因；不能让模型补出一个年龄、重量或活动强度。

## 2. 体重与 BMI

`BMI = weight_kg / (height_cm / 100)^2`。[R2]

本项目只作为体重与身高的描述指标。首版不自动应用地域、人群不同的体重分类阈值，不用 BMI 直接推断体脂或健身能力。

示例：70 kg、175 cm，BMI = 22.857142…，界面显示 22.86。缺体重、缺身高或非正数时不计算。

体重趋势使用实际测量点；七日均值取七个业务日内现有测量值，显示样本数。没有记录的日期不补为 0，也不凭固定“7700 kcal=1 kg”把单日差额换成体脂变化。

## 3. 静息能量消耗 REE：Mifflin–St Jeor

原始研究提供的简化方程如下，W 为 kg、H 为 cm、A 为周岁，输出 kcal/day：[R1]

| 原研究性别参数 | 方程 |
|---|---|
| 男性 | REE = 10W + 6.25H − 5A + 5 |
| 女性 | REE = 10W + 6.25H − 5A − 161 |

页面名称使用“静息能量消耗预测”。这是群体数据推导的预测方程，不是个人实测基础代谢。未指定方程所需性别参数或缺年龄、身高、体重时不计算。

示例：男性、25 岁、70 kg、175 cm，预测 REE = 1673.75 kcal/day；同输入的女性方程结果为 1507.75 kcal/day。

此 REE 数值单独展示，不能直接冒充下一节 FAO 定义的 BMR。项目不把 REE 与 BMR 两个名称混成同一个指标。

## 4. 全天能耗参考：来源 BMR 与 PAL

FAO 给出 TEE = BMR × PAL 的定义，PAL 描述长期整体活动，已包含习惯运动。[R2] 为保证同一来源口径，首版该模块使用 FAO 成人章节列出的 Schofield BMR 方程与 PAL 范围。[R3]

### 4.1 BMR 方程

W 为 kg，输出 kcal/day。源表年龄组写为 18–30、30–60；代码采用完整周岁半开区间，首版实际启用 19≤A<30 和 30≤A<60。30 岁边界归第二组，是本项目明确的边界实现约定。

| 参数组 | BMR 方程 |
|---|---|
| 男性，19≤A<30 | 15.057W + 692.2 |
| 男性，30≤A<60 | 11.472W + 873.1 |
| 女性，19≤A<30 | 14.818W + 486.6 |
| 女性，30≤A<60 | 8.126W + 845.6 |

### 4.2 PAL 区间

| 用户确认的长期活动类别 | PAL 来源范围 |
|---|---|
| LIGHT：久坐或较轻活动生活方式 | 1.40–1.69 |
| MODERATE：较活跃生活方式 | 1.70–1.99 |
| VIGOROUS：长期较高活动生活方式 | 2.00–2.40 |

来源范围描述生活方式类别，不是个人统计置信区间，也不是一次训练的强度评分。不要仅凭今天训练 30 分钟选择 PAL。缺长期活动类别时全天参考为空。

`TEE_low = BMR_estimate × PAL_low`；`TEE_high = BMR_estimate × PAL_high`。

示例：男性、25 岁、70 kg，BMR = 1746.19 kcal/day。LIGHT 类参考范围为 2444.666–2951.0611 kcal/day，界面可显示约 2445–2951 kcal/day。该值是来源方法下的长期日均参考，不能写为今天实测消耗。

该区间不再加一次运动热量，也不再加一次食物热效应。界面把运动记录作为独立参考展示；若未来加入全天活动时间账，需要另建完整方法与验证，不与当前 PAL 方法混用。

FAO 的方法有群体估算背景。本项目将其作为透明参考而非针对中国个体的准确测量；默认保持范围和来源可见。Mifflin REE 与 Schofield BMR 同时存在是因为用途不同，不能为了数值相近而替换概念。

## 5. 已记录运动能耗：标准 MET

汇编将标准 1 MET 近似定义为 1 kcal/kg/hour。[R4]

`E_gross_kcal = MET × weight_kg × duration_seconds / 3600`。

这是该活动时段的总能耗估算，含静息部分。若展示“相对标准静息的增量”，项目依据标准 1 MET 作如下派生：

`E_net_standard_kcal = max(MET − 1, 0) × weight_kg × duration_seconds / 3600`。

增量公式是对同一标准假设的算术派生，不声称测得个人静息消耗。两种口径单独命名、单独存储，不能同一图表混加。

示例只假定一个已核查条目的 MET=6，不指定实际动作：70 kg、30 分钟，总能耗估算 210 kcal，标准增量估算 175 kcal。

MET 必须匹配活动、速度或强度、适用年龄和来源版本。没有匹配条目时提示用户补充，不由模型随意填 6 或 8。动作的组数、次数或外部负重不能直接换算出可靠消耗；力量训练采用来源描述匹配的活动时段，休息是否包含以条目口径为准。

多个条目必须避免覆盖同一时段。若条目时长总和超过已记录场次时长，先标记冲突，不悄悄全加；时间不完整时结果名称保持“已记录运动估算”。

汇编明确指出标准/校正 MET 都不能替代直接测量，因此不提供“误差必定小于 10%”之类保证。[R5]

## 6. 饮食热量与营养

### 6.1 以来源密度计算

`E_kcal = grams × energy_kcal_per_100g / 100`。

`protein_g = grams × protein_g_per_100g / 100`，脂肪和碳水同理。各营养项单独处理未知：有热量但没蛋白质时，热量可计算、蛋白质为空。

来源可为可靠营养数据库、包装标签或用户主动提供的数据；快照记录出处、版本和生熟/做法。FoodData Central 提供数据与 API，但中式混合菜仍需对应食谱/营养数据，不能把英文条目的值任意贴到另一种做法。[R6]

算术示例使用虚拟输入而非食物库事实：某条目密度 165 kcal/100g、蛋白质 20g/100g，分量 150g；结果为 247.5 kcal、30g 蛋白质。

### 6.2 单位与标签

`kcal = kJ / 4.184`。[R2] 例如标签 418.4 kJ/100g = 100 kcal/100g；吃 200g 为 200 kcal。标签如果按“每份”给出，必须同时知道每份克重再转换。

FAO 给出一般宏量营养能量换算 4/4/9 kcal/g 等平均因素。[R2] 首版优先使用来源公布的能量值，不用粗略 4×蛋白质+4×碳水+9×脂肪覆盖标签值，纤维、酒精等还可能影响口径。未匹配能量条目时不默认猜一个热量。

照片可以帮助识别食物，但通常不能可靠确定克数、用油和隐藏配料。保存分量依据 WEIGHED/USER_ESTIMATE/IMAGE_ASSUMPTION/UNKNOWN；模型自报置信度不等于校准后的概率。

有依据的分量区间可按上下界计算情景范围，并说明区间假设；不能把这个范围包装为统计置信区间。缺乏任何分量依据时显示待补充。

### 6.3 当天摄入与差额

仅汇总 CONFIRMED 记录中的可计算条目，并显示无法计算的条目数。用户通过 daily_checkin 明确确认当天饮食是否全部记录。

若当天完整、每条能量均有计算值，设 I 为摄入估算、TEE 区间为 [L,H]，则“摄入减全天参考”区间为 `[I−H, I−L]`。负值表示在该参考方法下摄入较少，正值较多。这是算术比较，不能推断真实脂肪消耗、自动设极端饮食目标或给疾病处方。

例如 I=2300、[L,H]=[2444.666,2951.0611]，差额范围为 −651.0611 至 −144.666 kcal。若少记录一餐，或有一条能量不明，则不展示该完整差额。

## 7. 训练完成情况：项目定义的工程指标

以下指标用于记录与计划对比，来源类型为 ENGINEERING_METRIC。它们不是经过临床验证的训练有效性评分。

### 7.1 力量计划组数完成度

对每个计划动作 j，Pj 为计划组数，Cj 为对应用户确认完成的组数：

`completion_sets = Σ min(Cj,Pj) / Σ Pj × 100%`。

只统计匹配同一计划版本/日的动作。未知是否完成的组单独显示；实际次数是否达到目标范围另行判断。额外完成组数单独展示，不能补偿另一个动作完全未做。

例：两个动作分别计划 3 组、3 组，实际完成 5 组、0 组；完成度为 50%，额外组数 2。没有组数目标时该指标为空。

### 7.2 时长型计划完成度

对每项有时长目标的动作，Tj 为目标秒数，Aj 为对应记录秒数：

`completion_duration = Σ min(Aj,Tj) / Σ Tj × 100%`。

实际时长不明时标记数据不完整，不把它当真实零训练。例：目标 1800 秒、实际确认 900 秒，完成度 50%。组数完成度与时长完成度分别展示，首版不把两种单位拼成一个总分。

### 7.3 外部负重训练量

`volume_external_kg = Σ external_load_kg × reps`，只统计次数和外部负重已知的完成组。

只适合相同动作、相同记录口径的趋势比较。自重动作不能把人体体重直接当外部负重；未知负重不作为真实 0。同一动作的训练量变化也不等于肌肉增长率。

周报展示已确认训练场次数、各动作记录趋势、用户自报恢复信息和缺失项；不声称从这些记录精确测得恢复或训练刺激。

## 8. 费用公式与预算口径

费用规则属于供应商计价及项目账本规则，与健康公式分开。

`call_cost = (hit_tokens × hit_price + miss_tokens × miss_price + completion_tokens × output_price) / 1,000,000`。[R7][R8]

`task_known_cost = Σ call_cost`，每个实际发起的模型请求单独记账。思考 Token 若属于 completion_tokens 细分，不能再次增加到总输出数。

示例采用 2026-10-12 Flash 官方 CNY 高峰价：未命中输入 2 元/百万、输出 8 元/百万。假设某次调用 4000 未命中输入、1000 输出、0 缓存命中，核算为 0.016 元；两次相同用量为 0.032 元。它是算术示例，不是任何问题的固定价格。

发送前预估包括系统提示、历史、检索片段、工具描述与多次调用可能性。不得只对用户输入的十几个字计费。预占使用高峰档且不假设缓存；实际输出不完全已知，因此预算是应用侧控制，超限阻止后续请求，不保证供应商总账一分不差。

缺 usage 时 calculated_cost=NULL，状态 UNKNOWN，保留预占。若用量已知但价格档位不明，保守核算并明确标记。不要拿账户余额差值代替该调用账单。

| C01 | BMI：70kg、175cm | 22.857142…，显示 22.86 |
| C02 | REE：男性、25岁、70kg、175cm | 1673.75 kcal/day |
| C03 | REE：女性、其余同 C02 | 1507.75 kcal/day |
| C04 | REE 缺年龄或方程性别参数 | null + missing_fields；不补值 |
| C05 | BMR：男性、25岁、70kg | 1746.19 kcal/day |
| C06 | BMR：男性、30岁、70kg | 第二年龄组：1676.14 kcal/day |
| C07 | C05 + LIGHT | 2444.666–2951.0611 kcal/day |
| C08 | C07 另有运动总能耗 210kcal | TEE 不再加 210 |
| C09 | MET=6、70kg、1800秒 | gross=210，net_standard=175 kcal |
| C10 | 运动缺时长或来源 MET | null；不以训练组数推算 |
| C11 | 能量165/100g、蛋白质20/100g、150g | 247.5 kcal、30g蛋白质；说明为虚拟输入 |
| C12 | 标签418.4kJ/100g、200g | 200 kcal |
| C13 | 食物热量密度已知、蛋白质未知 | 能量可算，蛋白质 null |
| C14 | 当天用户未确认记录完整 | “已记录摄入”；完整差额不展示 |
| C15 | 计划组数[3,3]，完成[5,0] | 50%，额外2组 |
| C16 | 有氧计划1800秒、确认完成900秒 | 50% |
| C17 | 三个完成组：20kg×10次 | 外部负重训练量600kg；不解释为热量 |
| C18 | Flash高峰，未命中4000、输出1000 | 0.016 CNY；官方价变更时随新版本重新计算 |
| C19 | 用量没有返回 | 金额未知；不记0，保留预算预占 |
| C20 | 同一用量事件被处理两次 | 仅结算一次，不改变已结算总额 |

C01–C18 的示例算术已核对；C19–C20 是后续工程验收行为。上述不是对食物识别、ASR 或完整业务的实际测试结果。年龄边界、闰日生日、跨日预算及记录缺失还需在 Java 实现时加入适合的测试。

## 10. 原始与官方来源

- [R1] Mifflin MD et al., 1990, *A new predictive equation for resting energy expenditure in healthy individuals*. [PubMed PMID 2305711](https://pubmed.ncbi.nlm.nih.gov/2305711/)，[DOI](https://doi.org/10.1093/ajcn/51.2.241)。核对简化系数、单位、研究人群和 REE 概念。
- [R2] FAO/WHO/UNU, *Human energy requirements*, [Principles and definitions](https://www.fao.org/4/y5686e/y5686e04.htm)。核对 BMR、TEE、PAL、BMI、能量单位及一般营养能量因素。
- [R3] 同报告 [Energy requirements of adults](https://www.fao.org/4/y5686e/y5686e07.htm)，表 5.2/5.3。核对 BMR 系数、长期 PAL 分类及范围；实现的年龄边界约定单独标注。
- [R4] [2024 Adult Compendium](https://pacompendium.com/adult-compendium/)、[标准 MET 定义](https://pacompendium.com/)。核对年龄范围和标准 MET；实际活动须导入来源条目。
- [R5] [Compendium：Corrected METs](https://pacompendium.com/corrected-mets/)。核对估算误差及不能替代直接测量的限制。
- [R6] [USDA FoodData Central API Guide](https://fdc.nal.usda.gov/api-guide/)。核对数据接口与数据来源说明；具体营养值须按选定条目导入。
- [R7] [DeepSeek 模型与人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。报价是核查日期快照，会变更。
- [R8] [DeepSeek Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。核对 usage、输入缓存及输出细分口径。

工程指标、缺失值规则、资源限制、数据库事务和界面呈现属于本项目设计，不冒充来源研究提出的医学规则。

阅读顺序按上表进行。先完成 P1 基础业务，再开发 P2 Agent 与计费，最后接 P3 资料和教学视频。

在自己的全新 MySQL 8.4 环境运行：

```bash
mysql --default-character-set=utf8mb4 -u your_user -p < schema.sql
```

会创建 `fitagent` 数据库及表。若该数据库已有同名表，不要重复导入；用 Flyway 做后续迁移。正式调用前核查初始化中的供应商价格配置，配置本人的 API Key 和独立主加密密钥；密钥不能写入 SQL 或提交到 Git。

已核查字段、主键、索引、外键目标、类型与创建顺序的一致性。当前交付环境无 MySQL 服务，未真实执行导入；也未调用付费模型。健康算例仅完成算术核对，不代表已验证实际识别与转写准确率。

后续开始实施时，先要求 Codex 阅读全部文档，并按 P1 完成登录、档案、基础字典和记录接口。不要一次性要求生成所有功能，也不要把自研 Agent 替换为现成编排框架。
